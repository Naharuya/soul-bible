## 이벤트 정의

| 이벤트 | 발생 시점 | 발생하지 않는 경우 |
| --- | --- | --- |
| `cross_game_started` | 시작 버튼, 확정된 재시작, 완료 후 다시하기 | 화면 열기만 함, 일시정지 후 재개, 재시작 취소 |
| `cross_game_completed` | 여섯 번째 서로 다른 빛을 모음 | 중도 나가기, 이미 모은 빛 재터치, 완료 화면 재빌드, 마음카드 버튼 |

각 판의 시작·완료는 해당 동작당 한 번이다. 완료율은 같은 관찰 기간의 완료 횟수 / 시작 횟수이며 시작 0회는 계산하지 않는다. 재시작도 새 시도에 포함되므로 사람 수나 만족도와 같지 않다. 현재 이벤트에는 판 식별자가 없어 개별 시도의 정확한 소요 시간·이탈 위치는 계산하지 않는다.

이벤트는 기존 v1 계약을 따르며 `resourceRef: cross_light`, 시각, 이벤트 ID, 로컬 범위 참조만 담는다. 감정·대화·카드 본문은 포함하지 않는다. `EngagementController.crossGameAnalytics`로 두 이름의 기기 누적 집계를 읽을 수 있다. 기존 `EngagementEventBus.sink`는 외부 수집기 연결 지점이며 앱에는 아직 수집기가 연결되어 있지 않다. 로컬 ID를 여러 사용자나 기기의 고유 ID로 해석하면 안 된다. 원격 수집에는 서비스 선택 후 전달·실패·중복 처리 검증이 추가로 필요하다.

## 실기기 확인할 항목

1. 메뉴에서 게임 진입, 시작 전 화면과 48px 별빛 터치 확인.
2. 여섯 빛을 약 30초에 걸쳐 수집하고 최종 십자가 정렬·잔잔한 빛 확인.
3. 중간에 홈으로 나갔다 돌아와 진행이 일시정지되는지 확인.
4. 재시작 취소는 수집 상태 유지, 확정은 새 판으로 시작하는지 확인.
5. 말씀·행동 다음 게임을 완료해 마음카드 → 저장 → 성장 기록으로 이동. 실제 AI 호출이 필요한 앞 단계는 현재 범위에서 실행하지 않고 모의 응답 자동 테스트 결과와 구분한다.
6. 큰 글자와 움직임 줄이기 설정에서 터치·버튼·복귀 확인.

## Closed Beta 관찰 계획

기간은 참가자가 정해진 뒤 7일을 제안한다. 실제 배포·참가자 초대는 아직 하지 않았다.

- 첫 사용: 설명 없이 시작할 수 있는지, 다음 빛을 기다리는 동안 반응이 없다고 오해하는지 관찰한다.
- 완료 후: ‘조작이 쉬웠나요?’, ‘끝난 뒤 마음이 더 편안했나요, 비슷했나요, 불편했나요?’, ‘말씀과 자연스럽게 이어졌나요?’, ‘내일도 다시 해보고 싶나요?’를 묻는다.
- 중도 종료: 실패로 취급하지 않고 기다림·조작·시간 부족 등 종료 이유를 선택적으로 기록한다.
- 7일 후: 이벤트 시작/완료 집계와 실제 응답 수를 함께 보고한다. 완료율만으로 마음 안정 효과나 재방문 의향을 결론내리지 않는다.
- 개선 우선순위: 터치 오해·화면 잘림·돌아가기 문제를 먼저 고치고, 이후 기다림과 빛 연출을 조정한다.

익명 피드백 기록 양식: [cross_game_beta_feedback.csv](../cross_game_beta_feedback.csv). 테스트용 별칭만 사용하며 대화 원문·실명·연락처는 기록하지 않는다. 아직 응답 데이터는 없다.

## 자동 검증 결과

릴리스 APK 빌드 성공, SM-S908N USB 업데이트 `Success`, 앱 실행 요청 `Status: ok`. 설치 후 잠금 상태 재확인 결과 `showing=true`, `mKeyguardOccluded=false`여서 실제 플레이 테스트는 진행하지 못했다. 잠금 해제와 Analytics 서비스·베타 참가자 준비 여부를 사용자에게 확인 요청한 상태다.

Flutter 전체 70개 통과·기존 skip 1개. 게임 화면의 Flutter 위젯 테스트에서 시작·완료 이벤트 순서와 각각 한 번 발생, 재시작 취소·확정·반복 플레이 집계 및 컨트롤러 재생성 후 보존을 확인했다. 서버 이벤트 계약 테스트 1개 통과. 정적 분석 error/warning 0·기존 info 6개. 실제 AI 요청은 실행하지 않았다.
